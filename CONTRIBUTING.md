# Как дорабатывать проект

Описывайте редакторскую проблему, а не «признак машинного автора». Для нового
правила добавьте положительный и отрицательный пример. В примерах нельзя
выдумывать улучшения продукта и менять утверждения ради красивой формулировки.

Для дефекта линтера добавьте тест с исходником и ожидаемым диагностическим
кодом. Отдельно добавьте случай, где правило не должно срабатывать. Сохраняйте
защиту кода, цитат, плейсхолдеров и назначений ссылок.

```bash
python -m unittest discover -s tests -v
python scripts/run_evals.py
python scripts/validate_repo.py --refresh-manifest
python scripts/validate_repo.py
```

Обновление manifest — явное действие сопровождающего. Проверьте список файлов
до публикации. Не включайте реальные данные клиентов и результаты генерации
с личными сведениями. Добавляйте только синтетические либо разрешённые примеры.

Изменение скилла не становится качественным от одного успешного тестового
прогона: нужен слепой парный просмотр результатов с исходным скиллом и без него.
Протокол находится в references/evaluation.md.
