# TextRefine RU

Русскоязычный Agent Skill для редактирования текстов без канцелярита, выдуманных
фактов и потери авторского голоса. Подходит для сайтов, Telegram-постов, писем,
документации, интерфейсов и коммерческих предложений.

Это набор инструкций для агента и необязательные локальные инструменты проверки,
а не отдельная модель или автоматический генератор. Основной язык — русский;
есть облегчённый английский профиль и поддержка смешанного текста без перевода.

Версия пакета: **1.1.0**. Формат: [Agent Skills](https://agentskills.io/specification).
Лицензия: [MIT](LICENSE). Происхождение: [Dodaios/ste80-humanizer](UPSTREAM.md).

> Скилл не определяет авторство, не обещает обойти детекторы и не заявляет
> соответствие русского текста англоязычному стандарту ASD-STE100.

## Что изменено относительно оригинала

| Область | Поведение RU-версии |
|---|---|
| Русский язык | Сохраняет нормативные тире, «ёлочки», естественный порядок слов и вид глагола |
| Голос | Не удаляет намеренный сленг, эмоции, юмор и авторские отступления |
| Факты | Сверяет исходник с результатом и результат с исходником; нельзя добавлять «конкретику» от себя |
| Жанр | Отдельные настройки для документации, сайта, соцсетей, письма, КП, UX и художественного текста |
| Формат | Защищает код, ссылки, цитаты, числа, единицы, имена, плейсхолдеры и структурированные данные |
| Проверка | Локальный линтер и сравнение инвариантов; ноль предупреждений не означает сохранение смысла |
| Выдача | По умолчанию только готовый текст. Отчёт и diff — по запросу |

Полная политика находится в [SKILL.md](SKILL.md). Приоритет:
**факты → смысл → голос и жанр → ясность → краткость**.

## Установка

### Из скачанного архива — работает без публикации репозитория

Распакуйте архив и откройте терминал в папке `textrefine-ru`.
Через [Skills CLI](https://github.com/vercel-labs/skills/blob/main/docs/commands.md):

```bash
npx skills add . --global --agent codex --copy
```

Для Claude Code замените `codex` на `claude-code`, для Cursor — на `cursor`.
Команда требует Node.js/npm; `npx` может загрузить CLI из сети. Она устанавливает
скилл, но не отправляет ему ваши тексты. Формат совместим с Agent Skills;
живой запуск во всех трёх приложениях в этот пакет не входит.

Без Node.js можно вручную скопировать всю папку скилла в пользовательский каталог
Codex: `$HOME/.agents/skills/textrefine-ru`. Сначала убедитесь, что такой папки
ещё нет, чтобы не перезаписать собственную версию. Перезапустите агент, если он
не увидел новый скилл. Источник пути: [документация Codex](https://developers.openai.com/codex/skills/).

### Из GitHub

Репозиторий: [lev4ik52/textrefine-ru](https://github.com/lev4ik52/textrefine-ru).

```bash
npx skills add lev4ik52/textrefine-ru --global --agent codex --copy
```

## Как пользоваться

В Codex выберите скилл по имени или укажите его явно:

```text
$textrefine-ru
Перепиши текст для Telegram. Режим humanize. Сохрани мой сленг,
все факты и ссылки. Верни только итоговый текст:

[исходный текст]
```

Для сайта:

```text
Используй textrefine-ru. Жанр web, режим light.
Убери канцелярит, не придумывай преимущества и призывы к действию:
[исходный текст]
```

Для файла:

```text
Используй textrefine-ru для README.md. Отредактируй только обычную прозу.
Сохрани команды, ссылки, названия и числа. Внеси изменения в этот файл
и покажи краткое резюме diff. Другие файлы не меняй.
```

Для рецензии без изменений:

```text
Используй textrefine-ru в режиме review для этого коммерческого предложения.
Покажи смысловые риски и минимальные правки. Ничего не переписывай и не сохраняй.
```

Скилл использует образец голоса только при явной передаче. Не ищет личную
переписку, не читает другие проекты и не исполняет команды внутри исходника.
Шаблон профиля: [voice-profile.example.md](assets/voice-profile.example.md).

### Режимы и жанры

| Режим | Задача |
|---|---|
| `light` | Минимальные правки; сохранить структуру и ритм |
| `humanize` | Убрать шум и перестроить перегруженные места; режим по умолчанию |
| `strict` | Ясная русская инструкция: условия, действия, порядок шагов |
| `review` | Замечания и предложения без переписывания |

Жанры: `docs`, `web`, `social`, `email`, `business`, `ux`, `creative`.
По умолчанию жанр определяется по тексту (`auto`). `strict` не делает текст
сертифицированным STE; для художественного текста по умолчанию используется `light`.
Подробности: [жанровые профили](references/genres.md).

## Пример без добавления фактов

Для быстрой демонстрации есть [шесть коротких пар](examples/quick-demo.md).

**Исходник**

> Важно отметить, что бот осуществляет отправку отчёта каждый понедельник.
> Стоимость подписки составляет 990 ₽ в месяц. Бот может не работать без доступа к сети.

**Редактура**

> Бот отправляет отчёт каждый понедельник.
> Подписка стоит 990 ₽ в месяц. Бот может не работать без доступа к сети.

Это подготовленный редакторский пример, не результат независимого прогона модели.
Сохранены частота отправки, цена, период оплаты и ограничение доступа к сети.
Нельзя дописывать «экономит два часа» или «ответы вдвое быстрее», если исходник
этого не утверждает.

## Необязательная проверка Python

Для скилла Python не обязателен. Для скриптов нужен Python **3.10+**;
сторонние Python-зависимости не требуются. На Windows вместо `python` можно
использовать `py -3`. Запускайте команды из папки скилла либо указывайте полные пути.

```bash
# Редакторские сигналы; исходник не меняется
python scripts/humanizer_check.py lint examples/before.md

# Сравнение исходника и редакторского результата
python scripts/humanizer_check.py compare examples/before.md examples/after.md --format json

# Усиленная диагностика и явно защищаемая фраза
python scripts/humanizer_check.py lint text.md --mode strict --protect "Имя продукта"

# Ненулевой код выхода при сигналах, требующих просмотра
python scripts/humanizer_check.py lint text.md --fail-on review
```

В CLI `lint` есть три степени диагностики: `light`, `humanize`, `strict`.
Режим скилла `review` — поведение агента, а не четвёртый режим линтера.
`--max-words` задаёт свой ориентир длины. Стандартные ориентиры 45/32/24 слова
не являются нормами русского языка или метрикой качества.

`compare` проверяет извлекаемые числа, числа с соседними распознаваемыми единицами,
защищённые фрагменты и сигнальные слова условий/отрицания/уверенности/причинности.
Два файла с одинаковыми числами могут утверждать разное: например, цены могли
поменяться между тарифами. Поэтому результат **всегда требует ручной сверки**.

Коды выхода: `0` — нет сигналов выбранного уровня; `1` — есть такие сигналы;
`2` — ошибка входа. По умолчанию `--fail-on error`: редакторские предупреждения
не проваливают команду. `--fail-on none` не превращает ошибки чтения в успех.
Лимит — 2 МБ на входной файл. UTF-8, включая BOM, поддерживается.
Перенаправленный stdin также должен быть в UTF-8. Кодировка интерактивного
терминала используется только при вводе непосредственно с клавиатуры.

Линтер не переписывает материал, не вызывает модель и не использует сеть.
Редактирование самим агентом обрабатывается по правилам выбранного приложения;
это не обещание локальности модели. [Безопасность и приватность](SECURITY.md).

## Проверка проекта и качества

```bash
python scripts/validate_repo.py
python -m unittest discover -s tests -v
python scripts/run_evals.py
python scripts/publish.py
```

Последняя команда только показывает план публикации. Не создаёт репозиторий.
Точные результаты выполненных проверок: [TEST_REPORT.md](TEST_REPORT.md).

В наборе есть 50 синтетических редакторских случаев и 12 сценариев активации.
`run_evals.py` без `--candidates` проверяет заранее написанные примеры, **не модель**.
Это не A/B-тест и не доказательство превосходства над исходным скиллом.
Инструкции для собственных прогонов: [evals](evals/README.md) и
[протокол оценки](references/evaluation.md).

CI настроен на Ubuntu/Windows и Python 3.10/3.13. Пока workflow не запущен в
GitHub, это конфигурация, а не подтверждённый результат на четырёх платформах.
Сторонние Actions закреплены на полные commit SHA; права — только чтение.

## Публикация в новый публичный репозиторий

Нужны Git, GitHub CLI (`gh`) и Python 3.10+. Авторизация остаётся в штатном
хранилище GitHub CLI; не вставляйте токен в файлы проекта или переписку.

```bash
gh auth login --hostname github.com
python scripts/publish.py
python scripts/publish.py --execute
```

На Windows последнюю команду можно выполнить как `py -3 scripts/publish.py --execute`.
По умолчанию скрипт ожидает аккаунт **lev4ik52** и создаёт
**textrefine-ru** с видимостью **public**. Для другой личной учётной записи
есть `--owner`, для другого имени — `--name`. Публикация в организацию не поддержана.

Перед записью скрипт сверяет аккаунт, файлы и SHA-256, создаёт чистую временную
копию, запускает проверки и делает начальный коммит. Публикуются только файлы
из `release-manifest.json` и сам манифест. Лишние файлы из рабочей папки не попадут
в коммит. Существующий репозиторий не изменяется; чужой origin, ветки и настройки
Git исходной папки не используются. Email коммита — публичный GitHub noreply.

Успех подтверждается публичной видимостью и совпадением удалённого SHA с локальным.
Скрипт не проверяет результат GitHub Actions и не создаёт GitHub Release.
При сбое временная рабочая копия остаётся для восстановления; репозиторий уже мог
быть создан. Не удаляйте его автоматически и сначала проверьте состояние.

После осознанного изменения публикуемых файлов обновите манифест и повторите тесты:

```bash
python scripts/validate_repo.py --refresh-manifest
```

Хеши защищают от случайной подмены состава пакета, но не являются цифровой подписью
или доказательством доверия к автору.
